# Architecture assignment

Inspect the relevant implementation and constraints. Return a decision the main
agent can use, with these elements only as needed:

- Which boundary, interface, data flow or dependency must change, and why.
- The smallest viable design that fits the existing system.
- Credible alternatives and the decisive tradeoff, when there is a real choice.
- Compatibility, migration, operational or security implications relevant to this change.
- The implementation boundary and evidence that would verify the design.

Avoid speculative frameworks and abstractions. Identify unresolved assumptions;
separate decisions requiring user input from routine implementation choices.
Read-only by default. The main agent records consequential accepted decisions in
the project's existing format (or a short decision note if it has none).
